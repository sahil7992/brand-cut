- Creator: coderabbitai (CodeRabbit). No caption in the info.json.

- Duration 69.07 s, 2070 frames, 29.97 fps, 1920x1080 (16:9), stereo AAC.
- Source type: native screen/motion render, not filmed. No crop. Analysed at full frame (640 px wide frames for numbers).
- Song: Shazam found no match (0 matches), so it is licensed/library music. librosa tempo 136 BPM (beat 0.441 s), continuous bed at -17 to -20 dB for 66 s, then a 1.5 s silent tail. Visual events are NOT quantised to the beat grid (see Sound).

## Summary
A 69-second dark-mode SaaS explainer that obeys the hook / problem / product / proof / CTA structure with almost no stock imagery: every scene is a recreated UI object floating in black on a faint 1-px grid with an orange (#fc5406) rim light and heat glow. Arc: kinetic type states the problem ("AI agents write more code than any team can review") over faux code and "Agent" cursor pills (0-3.6) -> a white Slack notification pill pops (3.7) and a pointer clicks it -> it expands to a Slack channel where four messages pile up ("Hey, can you review my PR?" ... "Can you check this right now?") (3.7-10.9) -> the noise collapses to a single PR card, which flips into a GitHub PR list (11-15) -> viewfinder brackets and "is rarely the one that matters the most" (15.4-18) -> the list drives a highlighted row (18-22) -> "CodeRabbit Triage" lockup (22-24) -> Triage board, Display menu, property chips and three scoring tags URGENCY / RECENCY / MOMENTUM (24-35) -> a three-column board with heat moving to "Ready to merge" (35.5-40.8) -> "Triage evaluates every change" -> "High security risk" -> PR card (41-47.7) -> floating code windows and a typed retrieval query (48-54) -> "protecting the codebase" with a lock, NOISE and RISK tags (54-59.5) -> "Ready for review" button -> click -> spinner -> "Deployed" check (59.6-63) -> CodeRabbit logo -> "CodeRabbit Triage" -> "Available now" with the rabbit hopping onto "now" (63-67.4) -> fade to black (67.4-69).

## Flash profile (160x90 downscale at 29.97 fps)
- Mean relative luminance 0.000-0.308 (frame max), typical 0.003-0.03; per-second max 0.086 (4 s, white Slack pill). The film is one of the darkest possible comps.
- Floods (mean jump >= 0.10, changed fraction >= 0.25): exactly one - 3.70 s, +0.302 mean L, 38 % of pixels, decaying to 0.215 (3.74), 0.183 (3.77), 0.08 (4.5): a bright pill scaling down; not a symmetric up-and-down pulse. A secondary dip at 5.54 (-0.055, 35 % of pixels) when the pill grows into the dark window (below the 0.10 threshold).
- Max opposing transition pairs in any 1 s window: 0 above threshold; counting the 3.70 spike and the 3.74-3.80 recovery as one pair, the maximum is 1.
- Other big pixel changes (frame diff, not luminance): 40.34 (diff 15.1, the pan/blur cut), 7.41 (10.5), 36.57 and 27.73 (10.5), all dark-to-dark, mean L change < 0.01.
- Implication for a brand: use dark-to-dark cuts with blur dissolves; one white object popping onto black every 30 s is acceptable; keep any white pop under 40 % of the frame area.

## Why this does not look AI-generated
1. Everything is a recreated, readable UI (named people, times, real PR titles, "+2,332 -12,454" diff stats, mono #25932 ids) rather than a generated screen with pseudo-text. Names, avatars and numbers are consistent between scenes.
2. One accent colour. Orange #fc5406 for rim light, "review", "rarely", "matters", "every", the logo and the rabbit; all other colour is functional (green deploy, red risk, Slack blue) - the palette is a system.
3. Real depth cues without photorealism: perspective planes with rim light, distant panels blurred 8-20 px, near panels sharp, parallax speeds ordered by depth.
4. Intentional easing: exponential-out scale-down on the pill (2.8, 7.5, 4.7, 3.4... %), pointer decelerates in 0.15 s then 0.5 s, anticipation dip in the brackets push-in (59 -> 42 -> 57 %). These are hand-set curves, not default ease.
5. Typography is a system: Inter-like grotesk for narrative, mono caps for scoring tags, SF-style UI text for chips; word-by-word stagger 0.15-0.30 s with blur 8 px; "review"/"rarely"/"matters" coloured, never whole sentences.
6. Text replace animations are mechanical: backspacing letters one by one, scramble per character when typing a tag, pill that keeps its outline while the words inside change - state changes with continuity, not cross-fades.
7. Pixel-art pointer with chromatic fringe and an orange click ripple; the pointer is a character in shots 2, 12 and 21 and always decelerates into its target.
8. Flash-safe luminance: only one white object in 69 s, everything else dark-on-dark; blur dissolves instead of flashes.
9. Sound: continuous bed plus ~28 LF hits and ~28 HF ticks, each on a UI event (click 61.7, deploy 62.8, rabbit landing 66.5); silence dip at 9.5-9.7 before the fourth message and a real silent tail.
10. Consistent camera: one slow push per scene, cuts always hidden behind blur or a container transform; no cuts to unrelated imagery.

## What would make it look AI
1. Generic "dashboard" with unreadable lorem-ipsum glyphs and mismatched fonts; here every string is real.
2. Neon glow on everything (all cards, all text) rather than a single warm rim light plus a controlled bloom behind one object (the bracket scene).
3. Cross-fades between every scene with no shared element; here the pill becomes the window, the capsule becomes the tag, the button becomes the logo.
4. Symmetric easing (ease-in-out) on all moves with the same 0.6 s duration; here durations range 0.1 s (card flip) to 5 s (code-window drift).
5. Floating 3D UI with random rotations and a wobbly perspective instead of a controlled 55-60 degree tilt that flattens.
6. A stock cursor arrow or none at all; no click feedback.
7. Generated voice-over/stock b-roll of laptops; the film has no people, no stock.
8. Strobing: a white flash on every transition (this film has one pop).
